# Real Provider Verification

The exact request content was generated by production prompt builders from a
read-only clone of the representative revision-399 save. Network calls use the
configured Low profile (`glm-5.3`, Custom Endpoint ending `/v1`) through the local
host's chat-completions backend. No profile, secret, user message or game State was
changed. No automatic retry or reasoning-content fallback was used.

The durable reservation ledger is [provider-calls.jsonl](./provider-calls.jsonl).
Only final `content` is used; raw responses are private temporary files outside
the repository. All failures retain their reservation conservatively.

Two findings and corrections:

1. ID1 used a JSON code fence. The first verifier bypassed the host's existing
   `extractJsonFromData` step and incorrectly treated this as product failure.
   The verifier now executes the exact AST-extracted production
   `extractMessageFromData`/`extractJsonFromData` functions at that boundary.
   The original response passes. No production parser change was needed.
2. ID2 added `sceneProgression.confidence`. Strict auxiliary object parsing
   discarded its otherwise valid evidence. The new bookkeeping return schemas
   now strip unknown keys while preserving required fields, length limits,
   enums and downstream authority/evidence guards. A focused red-then-green test
   reproduces this. The same original ID2 response then passes.

## Local Findings

- Reservation 5: verifier startup omitted config-path initialization and exited
  before any generation. Marked `not_dispatched`, zero generation calls, but the
  reservation remains counted conservatively.
- ID6: configured Qwen 1.7b request returned HTTP400 before generation because
  the generated grammar could not initialize. The new Actor descriptor included
  2000/3000-character string limits, above llama.cpp's repetition sanity bound.
  Local-only grammar now omits those large generation-time bounds; unchanged Zod
  validation still enforces them on return. This is not a provider/JSON fallback.
- ID7: local daemon was offline when the request was forwarded; no output.
  The project-local daemon was restarted using its existing binary/models.
- ID8: grammar succeeded, but response terminated at `eval_count=1024`,
  `done_reason=length`, leaving 3371 characters of incomplete JSON.
  Shared Post response reserve increased to 2048; input cap decreases from
  28672 to 24576 characters at unchanged 8192 total context. Existing compaction
  protects narration. Current measured initial Local is 23837 and supplementary
  Local 24523, both fit.
- ID9: 2048 reserve returned complete JSON: 1972 tokens, 6926 characters,
  36079 ms, `done_reason=stop`. Seven candidate families failed semantic guards
  (temporal, temporary Actor, first impression, pacing, history, Actor activity,
  Material evidence). Conservative integration preserved prose and committed
  only accepted outcomes. This is not a clean first-response quality pass.
- ID10: one supplementary request built from ID9's actual failed groups and
  immutable accepted constraints returned 519 tokens / 1827 characters in
  12704 ms, `done_reason=stop`. Untouched response passed all selected-family
  guards and bounded merge, then the isolated guarded commit; prose unchanged.

The upstream grammar limitation is documented at
https://github.com/ggml-org/llama.cpp/issues/25923 and
https://github.com/lemonade-sdk/lemonade/issues/2691.
Local complete response plus one selected supplement is verified. First-pass
Local semantic quality remains a residual risk; do not label ID9 a no-error pass.
The final tally is 10 reserved slots, 4 remote generations, 5 Local dispatch
attempts (including service/grammar failures), and 1 pre-dispatch script failure.
No further requests are allowed by the scripts. No user save was modified.

## Limits

These are real model outputs and production parsing/guard/reducer/guarded-save
verification, but State/chat persistence uses isolated memory callbacks rather
than modifying the user's save. Backend requests bypass browser preset assembly;
the configured profile has no explicit preset. Full app recovery and display
acceptance remains open. Successful historical-Post fixtures do not reconstruct
the lost content of the earlier failed user turn.
